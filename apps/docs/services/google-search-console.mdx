# Google Search Console

Google Search Console provides search analytics data: top queries with clicks, impressions, CTR, and average position, plus date-based trend data.

## What it powers

- **SEO Performance widget** -- Top queries table with all metrics
- **SEO expanded view** -- Click/impression trend charts and summary KPIs

## OAuth setup

Google Search Console uses an OAuth broker because Google requires a stable HTTPS redirect URL for public apps. Radarboard can use the managed broker at `https://auth.radarboard.app`, or an organization can run its own broker and point the app configuration at that broker.

When a user connects Google Search Console, they authorize their own Google account. The managed broker stores the Google refresh token encrypted at rest so it can issue short-lived access tokens to the local app. The local macOS app stores only an opaque broker token. The broker does not store Search Console reports, queries, clicks, impressions, or site performance data.

<Steps>
  <Step title="Create a Google Cloud project">
    Go to [console.cloud.google.com](https://console.cloud.google.com/). Create a new project (or use an existing one).
  </Step>
  <Step title="Enable the Search Console API">
    In the API Library, search for **Google Search Console API** and enable it.
  </Step>
  <Step title="Create OAuth2 credentials">
    Go to **APIs & Services** > **Credentials** > **Create Credentials** > **OAuth 2.0 Client ID**.
    
    Select **Web application** as the application type. For the managed broker, add this Authorized redirect URI:

    ```text
    https://auth.radarboard.app/api/auth/google/callback
    ```
    
    If you self-host the broker, use your broker domain with the same path: `/api/auth/google/callback`.
  </Step>
  <Step title="Configure the broker">
    Configure the broker deployment with the Google OAuth client values and a durable encrypted credential store. The local app uses the managed broker by default; self-hosted builds can point app configuration to a different broker URL.
  </Step>
</Steps>

## Broker configuration

Managed broker URL:

```text
https://auth.radarboard.app
```

Self-hosted broker deployments need these configuration values:

```text
OAUTH_GOOGLE_CLIENT_ID=xxxxxxxxxxxx.apps.googleusercontent.com
OAUTH_GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxx
RADARBOARD_OAUTH_BROKER_URL=https://auth.radarboard.app
```

For self-hosted brokers, replace `RADARBOARD_OAUTH_BROKER_URL` with your own HTTPS broker origin.

## Privacy and storage

| Item | Stored by managed broker? | Notes |
|------|----------------------------|-------|
| Google refresh token | Yes | Encrypted at rest; required to refresh access without asking the user to reconnect. |
| Google access token | Temporarily | Short-lived token used to read Search Console data. |
| Local app broker token | Yes, locally | Opaque token stored by the local app; it is not the Google refresh token. |
| Search Console reports | No | The broker does not persist clicks, impressions, queries, CTR, rankings, or site report data. |
| Self-hosted broker option | Yes | Advanced users can run their own broker and configure the app to use it. |

## API details

| Property | Value |
|----------|-------|
| API base URL | `https://searchconsole.googleapis.com/webmasters/v3` |
| Rate limit | Standard Google API quotas |
| Cache TTL | 5 minutes |
| Authentication | OAuth2 through managed or self-hosted broker |
